## 需求
### 需求：批量同步历史素材到 ChromaDB
系统必须支持批量将 MySQL 中的历史素材同步到 ChromaDB，生成真实语义向量嵌入（不再使用零向量占位）。

#### 场景：成功批量同步
- **当** 执行向量同步工具
- **那么** 系统遍历所有未向量化的素材，通过 embedding 服务批量生成真实语义向量并添加到 ChromaDB

#### 场景：分批处理
- **当** 同步超过 100 个素材
- **那么** 系统分批次处理，每批最多 100 个，避免内存溢出

#### 场景：跳过已存在的向量
- **当** 素材在 ChromaDB 中已存在有效向量
- **那么** 系统跳过该素材，不重复生成

#### 场景：embedding 服务不可用时不中断
- **当** 同步过程中 embedding 服务不可达
- **那么** 系统记录错误并跳过该批次，不使同步进程崩溃

### 需求：向量化文本生成
系统必须为每个素材构建用于生成向量的文本，包含描述、标签、文件名。

#### 场景：构建向量文本
- **当** 为素材生成向量
- **那么** 系统组合 description + tags + filename 作为向量文本

#### 场景：空描述处理
- **当** 素材描述为空
- **那么** 系统仅使用文件名和标签生成向量

### 需求：同步进度跟踪
系统必须记录向量同步进度，支持中断后继续。

#### 场景：记录同步进度
- **当** 完成一批同步
- **那么** 系统记录已处理数量和当前批次

#### 场景：中断后继续
- **当** 同步过程中断后重新启动
- **那么** 系统从上次中断点继续，不重复处理

### 需求：向量更新支持
系统必须支持更新现有素材的向量表示。

#### 场景：更新描述后同步向量
- **当** 素材描述被手动更新
- **那么** 系统重新生成向量并更新 ChromaDB 记录

#### 场景：强制重新向量化
- **当** 用户触发强制同步
- **那么** 系统忽略现有向量，为所有素材重新生成向量


### 需求：维度变更触发全量重建
当 embedding 向量维度发生变更时，系统必须支持清空旧向量并以新维度全量重建，避免维度不匹配导致检索失败。

#### 场景：清空并重建 content_dedup 集合
- **当** 向量维度由 1536 变更为 1024 且执行全量重建
- **那么** 系统清空 content_dedup 集合的旧向量，从 MySQL 发帖历史重新生成真实向量写入

#### 场景：重建后去重恢复正常
- **当** 全量重建完成后对一篇全新内容执行去重检测
- **那么** 相似度反映真实语义，不再恒为 1.000

### 需求：素材向量写入幂等
系统对同一素材（以稳定 id 标识）写入向量时必须幂等，重复处理同一素材不得在向量库中产生多条记录，且删除素材时必须能正确移除其向量。

#### 场景：同一素材重复处理不累积
- **当** 同一素材（相同 path/id）被多次处理或同步
- **那么** 向量库中该素材只保留一条向量记录（更新而非新增）

#### 场景：素材向量 id 前缀一致
- **当** 写入、重建、删除素材向量
- **那么** 三者使用一致的向量 id（统一 `material_` 前缀），删除操作能命中并移除对应向量

#### 场景：重建前真正清空
- **当** 执行素材索引全量重建且启用清理
- **那么** 系统先真正清空集合已有向量，再回填，避免与历史向量叠加导致净增

### 需求：向量检索前确保存储已初始化
系统在执行素材语义搜索、主题推荐等向量检索前，必须确保对应向量存储已初始化，不得因未初始化而静默返回空结果。

#### 场景：检索时懒初始化
- **当** 调用素材语义搜索或主题推荐且对应存储尚未初始化
- **那么** 系统先完成初始化再检索，返回真实结果而非空

### 需求：素材向量基于大模型图片描述
素材向量化必须优先使用大模型（Vision）为图片生成的自然语言描述作为向量文本来源，以保证语义检索质量；描述必须随素材记录持久化。

#### 场景：描述持久化
- **当** 素材整理调用 Vision 生成图片描述
- **那么** 该描述随素材记录一并存入数据库，不被丢弃

#### 场景：向量文本使用描述
- **当** 为素材生成向量
- **那么** 系统使用图片描述（结合标签）作为向量文本，而非仅文件名

#### 场景：无描述时的退化
- **当** 素材没有可用的大模型描述
- **那么** 系统退化为使用文件名与关键词构建向量文本，不报错

#### 场景：写入与重建向量文本一致
- **当** 分别通过常规写入路径和全量重建路径为同一素材生成向量
- **那么** 两者使用一致的向量文本构建逻辑
